# Graphics Stack: Metal 4, MetalFX, D3D11, and Vulkan

The port factory supports three Windows graphics APIs on Apple Silicon — **Direct3D 12**,
**Direct3D 11.0/11.1**, and **Vulkan** — without Wine, CrossOver, or D3DMetal.

## 1. Crate Boundaries

One strict architectural rule keeps this stack maintainable: **`crates/win32-rt` never imports
`objc2-metal`.**

| Crate / Module | Responsibility |
|---|---|
| `crates/d3d12-metal` | Architecture-neutral D3D12 state/format/layout/trace types plus the entire **Metal 4** + **MetalFX** backend (`metal/*`, `mesh.rs`, `rt/*`). This is the only runtime graphics crate that talks to Metal 4. |
| `crates/win32-rt/src/d3d12/` & `dxgi/` | Windows COM vtables for DXGI (`IDXGIFactory1`..`7`, `IDXGIAdapter4`, `IDXGISwapChain4`) and D3D12 (`ID3D12Device`..`10`, `ID3D12GraphicsCommandList`..`7`, queues, fences, state objects, debug/DRED). Translates COM calls into safe Rust calls on `d3d12-metal`. |
| `crates/win32-rt/src/d3d11/` | Real **Direct3D 11.0 / 11.1** COM runtime (`ID3D11Device1`, immediate & deferred `ID3D11DeviceContext1`, `IDXGIDevice1`, `IDXGISurface1`, `IDXGISwapChain4`). Runs on `d3d12-metal` + `dxil-metal`, with zero direct Metal calls. |
| `crates/win32-rt/src/misc/vulkan_1.rs` | Dynamic **Vulkan** loader bridge to `libMoltenVK.dylib` (translating `VK_KHR_win32_surface` → `VK_EXT_metal_surface` over `CAMetalLayer`). |
| `crates/d3d12-replay` | Standalone CLI to inspect binary D3D12 traces, validate invariants, extract embedded shaders, and replay captures on Metal 4. |

## 2. Direct3D 12 → Metal 4 (`crates/d3d12-metal`)

| D3D12 Concept | Metal 4 Implementation |
|---|---|
| `ID3D12Device`..`10` | `MTLDevice`, `MTL4Compiler`, and a global `MTLResidencySet` (`metal/mod.rs`, `metal/device.rs`) |
| `ID3D12CommandQueue` / `ID3D12Fence1` | `MTL4CommandQueue` + `MTLSharedEvent` (`metal/queue.rs`, `Queue::execute_command_lists`) |
| `ID3D12CommandAllocator` / `ID3D12GraphicsCommandList`..`7` | `MTL4CommandAllocator` + `MTL4CommandBuffer` (`metal/cmdlist.rs`) |
| `ID3D12Heap` / `ID3D12Resource2` | `MTLHeap` / `MTLBuffer` / `MTLTexture`, plus a companion `R8Uint` stencil texture for planar `D32_FLOAT_S8X24_UINT` (`metal/heap.rs`, `metal/resource.rs`) |
| `ID3D12DescriptorHeap` (CBV/SRV/UAV, Sampler, RTV, DSV) | 24-byte `IRDescriptorTableEntry` GPU buffer (`metal/descriptor.rs`, `metal/views.rs`), CPU RTV/DSV tables, and `UavTrack` clear-lookup tracking with automatic cleanup on `Resource::drop` |
| `ID3D12RootSignature` | `dxil_metal::RootSignature` + top-level argument buffer uploaded into the per-command-list ring |
| Compute / Graphics / Mesh PSOs | `ComputePipeline`, `GraphicsPipeline` (`metal/pipeline.rs`), `MeshPipeline` (`mesh.rs`), cached on disk via `MTL4Archive` (`dxil-metal::pso_cache`) |
| DXR 1.1 (`ID3D12StateObject`, AS build/refit/compact, `RayQuery`, `DispatchRays`) | `MTLAccelerationStructure`, GPU instance-descriptor conversion kernels, `MTLVisibleFunctionTable`, `MTLIntersectionFunctionTable`, `RaygenIndirection` (`rt/accel.rs`, `rt/pipeline.rs`, `rt/kernels.rs`) |
| `IDXGISwapChain4` | `CAMetalLayer` attached to the `NSWindow` (or a headless `MTLTexture` ring when `HWND` is null) (`metal/swapchain.rs`, `metal/present_thread.rs`) |

### Key D3D12 Behaviors

- **Planar depth-stencil & block-compressed copies (`metal/cmdlist.rs`):** `CopyTextureRegion` and
  `CopyResource` handle planar `D32_FLOAT_S8X24_UINT` (`R32_FLOAT_X8X24_TYPELESS` plane 0 = depth,
  `X32_TYPELESS_G8X24_UINT` plane 1 = companion `R8Uint` stencil), BC1–BC7 block-aligned footprints
  on small mips, and cross-format typeless/sRGB copies via `newTextureViewWithPixelFormat`.
- **Clears & MSAA resolves (`metal/clear.rs`, `metal/cmdlist.rs`):** RTV and DSV clears handle
  multi-slice 2D array / 3D views and scissor rects (load action when unclipped; rasterized clear
  quad when clipped or preserving partial slices). UAV float/uint clears cover typed and raw
  (`R32_TYPELESS`) buffers and 1D/2D/2DArray/3D textures with optional rects. `ResolveSubresource`
  resolves MSAA targets in a transient Metal 4 render pass.
- **Dynamic state, predication & `ClearState`:** Supports `OMSetStencilRef`,
  `OMSetFrontAndBackStencilRef`, `ClearState(pPipelineState)`, and `SetPredication`.
- **Function constants & fallback vertex layouts (`metal/pipeline.rs`, `mesh.rs`):** Stages that
  emit Metal function constants automatically wrap in `MTL4SpecializedFunctionDescriptor`. When a
  PSO's input layout omits a vertex shader input, `GraphicsPipeline::new` infers the component type
  from the DXBC `ISG1`/`ISGN` signature and binds a constant step-rate fallback on the last slot.
- **`ExecuteIndirect` with embedded index buffers (`metal/indirect.rs`):** Committed D3D12 buffers
  and buffer-only placement heaps allocate with `StorageModeShared` on Apple Silicon unified memory,
  so `ExecuteIndirect` can read GPU-compacted indirect commands with embedded
  `D3D12_INDEX_BUFFER_VIEW`s mixing `R16_UINT` and `R32_UINT`. When CPU-visible index buffer views
  aren't populated yet, the GPU expander (`port_execute_indirect`) expands commands into dual-slot
  `(UInt16, UInt32)` ICB records.
- **Sound cross-engine barriers:** Engine-specific shortcuts like `AW2_IB_BINDLESS_WAR` stay **OFF
  by default** so barrier ordering remains valid for any D3D12 engine.

### Native MetalFX Upscaling (`metal/metalfx.rs`)

When a game calls an upscaler hooked into `CommandList::upscale_temporal` or
`CommandList::upscale_resource` (such as `amd_fidelityfx_loader_dx12!ffxDispatch` with
`FFX_API_DISPATCH_DESC_TYPE_UPSCALE` or `nvngx_dlss!NVSDK_NGX_D3D12_EvaluateFeature`), `d3d12-metal`
drives Apple's native **`MTL4FXTemporalScaler`** and **`MTL4FXSpatialScaler`** from
`MetalFX.framework` (loaded via `dlopen` + Objective-C runtime dispatch, so builds don't hard-link
the framework):

- **Temporal path (`MTL4FXTemporalScaler`, default ON):** Used automatically whenever the game
  provides color, depth (including `Depth32Float_Stencil8`), and motion vectors. `amd_fidelityfx_loader_dx12`
  supplies exact FSR3 Halton `(base 2, base 3)` subpixel jitter phases/offsets, forwards `jitterOffset`,
  `motionVectorScale`, `depthReversed`, `preExposure`, `autoExposure`, `reactiveMask`, dynamic
  resolution, and macOS/iOS 27 `outputResolutionMotionVectorsEnabled` / `jitteredMotionVectorsEnabled`,
  and converts non-`R16Float` 1×1 exposure textures (e.g. `R32Float`) into a cached 1×1 `R16Float`
  scratch texture automatically. Runs from `1.0×` (Native AA) up to `3.0×` (Ultra Performance).
- **Spatial fallback (`MTL4FXSpatialScaler`):** Used when depth/motion vectors are absent,
  `PORT_METALFX_TEMPORAL=0`, or temporal scaling is unsupported for a given format/scale. Uses
  `Linear` color processing for float HDR formats (`RGBA16F`, `RG11B10F`, `RGBA32F`) to avoid
  reversible-Reinhard quantization/clamping on pre-exposed HDR buffers, and copies `1:1` native
  resolution losslessly without running the spatial filter.
- When the destination texture already satisfies MetalFX's required usage and `Private` storage,
  MetalFX writes straight to it (zero-copy). Otherwise `metalfx.rs` uses a cached private scratch
  texture and blits into the destination.
- Set `PORT_METALFX_TEMPORAL=0` (or `AW2_METALFX_TEMPORAL=0`) to disable temporal MetalFX and force
  spatial MetalFX (`jitterPhaseCount = 1, jitter = 0`). Set `PORT_METALFX=0` (or `AW2_METALFX=0`) to
  disable MetalFX completely and force the built-in bilinear compute shader (`port_upscale_2d_f`).

### Opt-in Metal 4.1 (`macOS 27` / `iOS 27` / MSL 4.1) Enhancements (`m41.rs`, `dml_gpu.rs`)

All Metal 4.1 runtime enhancements are opt-in (default OFF so baseline Metal 4 behavior, disk cache
keys, and macOS 26 compatibility remain untouched). Set master `PORT_METAL41=1` to enable the whole
suite, or toggle individual sub-knobs (each overrides `PORT_METAL41`):

- `PORT_METAL41_VIEW_MIN_LOD`: hardware `MTLTextureViewDescriptor.minLOD` views on `Apple10`+ GPUs
  for D3D12 SRV `ResourceMinLODClamp` and D3D11 `ID3D11DeviceContext::SetResourceMinLOD` (falls
  back cleanly to descriptor-table `min_lod_clamp` on `Apple9` and earlier).
- `PORT_METAL41_BLOCK_READ`: MSL 4.1 multipixel `block_read<2, 1>` + SIMD reduction /
  release-atomic variants (`*_b2`) for internal `clear.rs` utility kernels.
- `PORT_METAL41_METALFX_OFFSETS`: zero-copy `MTL4FXTemporalScaler` content/output subrect offsets
  (`colorContentOffsetX/Y`, `depthContentOffsetX/Y`, `motionContentOffsetX/Y`,
  `reactiveMaskContentOffsetX/Y`, `outputOffsetX/Y`) bypassing intermediate scratch blits.
- `PORT_METAL41_RGB32_TBUF`: read-only `MTLPixelFormatRGB32{Float,Uint,Sint}` typed texture-buffer
  SRVs (`Buffer<float3|uint3|int3>`) gated strictly on `MTLGPUFamily::Apple10`+.
- `PORT_METAL41_DIRECTML_GPU`: GPU offload for DirectML `GEMM` (`FLOAT32`/`FLOAT16`, batched,
  transposed, bias, fused activations) via MSL 4.1 `tensor_inline` + `mpp::tensor_ops::matmul2d`.
- `PORT_METAL41_FORWARD_PROGRESS` (`auto|weak|simdgroup_parallel`),
  `PORT_METAL41_CONTENTION_RELIEF` (`auto|none`), and `PORT_METAL41_PERSISTENT_KERNEL` (`0|1`):
  `MTL4ComputePipelineDescriptor` scheduling hints (auto-suppresses persistent optimization when
  `weak` is set; salts PSO cache keys only when active).

### Binary Trace & Offline Replay (`trace.rs`, `crates/d3d12-replay`)

The binary trace format (`AW2D3D12\0`, v1) captures 92 opcodes across device, resource, descriptor,
PSO, command list, queue, fence, swapchain, mesh shader, and DXR calls (including `ClearState`,
`SetPredication`, split front/back stencil ref, and clear rects). `d3d12-replay` validates command
streams, extracts shaders, and replays captures directly onto Metal 4 without running the game.

## 3. Direct3D 11.0 / 11.1 on Metal 4 (`crates/win32-rt/src/d3d11/`)

`d3d11.dll` is a real COM runtime — not a stub — translating D3D11 directly onto `d3d12-metal` and
`dxil-metal`:

- **Entry points:** `D3D11CreateDevice`, `D3D11CreateDeviceAndSwapChain`, `D3D11On12CreateDevice`
  (negotiates feature levels `11_1` down to `9_1`; opt out with `PORT_D3D11=0` to return
  `DXGI_ERROR_UNSUPPORTED`).
- **COM surface:** `ID3D11Device` / `ID3D11Device1` (50 vtable slots), immediate and deferred
  `ID3D11DeviceContext` / `ID3D11DeviceContext1` (134 slots), `ID3D11CommandList`,
  `IDXGIDevice1`, `IDXGISurface1`, `IDXGISwapChain4`, buffers, 1D/2D/3D textures, RTV/DSV/SRV/UAV
  views, shaders, input layouts, samplers, blend/rasterizer/depth-stencil states, and queries.
- **Data movement & execution:** `Map`/`Unmap` (`WRITE_DISCARD`, `WRITE_NO_OVERWRITE`, `READ`),
  `UpdateSubresource`, `CopyResource`, `CopySubresourceRegion`, `ClearRenderTargetView`,
  `ClearDepthStencilView`, `ClearUnorderedAccessView*`, `Draw*`, `Dispatch*`, and deferred context
  record/replay (`FinishCommandList` / `ExecuteCommandList`).
- **Shaders:** Legacy FXC SM 4/5 bytecode (`SHEX`/`SHDR`) passes through `libdxilconv.dylib` →
  signed DXIL → Metal Shader Converter (`dxil-metal`) → Metal 4 PSOs.
- **Honest limits:** Geometry, hull, and domain shader creation return `E_NOTIMPL` / unsupported
  explicitly rather than pretending to bind them.

## 4. Vulkan → MoltenVK (`crates/win32-rt/src/misc/vulkan_1.rs`)

`vulkan-1.dll` bridges Windows Vulkan 1.0–1.3 applications onto macOS Metal through MoltenVK:

- Dynamically `dlopen`s `libMoltenVK.dylib` (falling back to `libvulkan.1.dylib` / `libvulkan.dylib`,
  or `$PORT_VULKAN_DYLIB`). Install MoltenVK on macOS with `brew install molten-vk`.
- Rewrites instance extensions automatically: translates `VK_KHR_win32_surface` to
  `VK_EXT_metal_surface` (or `VK_MVK_macos_surface`) and injects `VK_KHR_portability_enumeration` +
  `VK_INSTANCE_CREATE_ENUMERATE_PORTABILITY_BIT_KHR` when advertised by the host loader.
- `vkCreateWin32SurfaceKHR` resolves the Win32 `HWND` to its `CAMetalLayer*` via
  `win32_rt::macos::metal_layer_for_hwnd` and creates a Metal surface.
- Forwards 64 core and KHR entry points directly. Because `win64_abi` lowers `extern "win64"` to
  AAPCS64 `extern "C"` on ARM64, MoltenVK's native function pointers match the calling convention;
  any non-intercepted proc returned by `vkGetInstanceProcAddr` / `vkGetDeviceProcAddr` is registered
  via `register_native_va` so `x86-runtime` can call it directly.
- When MoltenVK is absent on the host, every entry point returns an honest Vulkan error
  (`VK_ERROR_INCOMPATIBLE_DRIVER` / `VK_ERROR_INITIALIZATION_FAILED` / `VK_FALSE`) with zeroed
  output handles — never fake handles.

## 5. Verification Suites

```sh
# Metal 4 D3D12 unit + MetalFX tests (173 tests)
cargo test -p d3d12-metal --lib --target aarch64-apple-darwin -- --test-threads=1

# Direct3D 11 (10 tests, including SM 5.0 compute + VS/PS draw on Metal 4) & Vulkan (6 tests)
cargo test -p win32-rt --lib --target aarch64-apple-darwin -- d3d11 misc::vulkan_1 --test-threads=1

# Metal 4 GPU integration tests (crates/d3d12-metal/tests/)
cargo test -p d3d12-metal --test gpu_clear_resolve --target aarch64-apple-darwin -- --test-threads=1
cargo test -p d3d12-metal --test gpu_mesh --target aarch64-apple-darwin -- --test-threads=1
cargo test -p d3d12-metal --test gpu_rayquery --target aarch64-apple-darwin -- --test-threads=1
cargo test -p d3d12-metal --test gpu_dispatch_rays --target aarch64-apple-darwin -- --test-threads=1
cargo test -p d3d12-metal --test gpu_rfx_psos --target aarch64-apple-darwin -- --test-threads=1
```

To run with Metal API validation enabled, prefix any GPU test with `MTL_DEBUG_LAYER=1`.
